--- User Story 5 ---
> **As a** user chatting with the textbook assistant,
> **I want** the system to provide an "agentic" experience that intelligently cross-references sections and chapters—even when I do not explicitly use commands in my prompt—

##### Acceptance Criteria

1. **Insufficient Information Handling:** If the main LLM evaluates its retrieved response as having insufficient information, it dynamically deploys a subagent with a custom prompt produced by the main LLM to gather extra data.
2. **Summary File Consultation:** The subagent or orchestrator reads from a pre-generated file containing summaries of each chapter and section to intelligently issue specific chapter/section commands.
3. **Recursive Delegation & Depth Limits:** Subagents may deploy subsequent subagents, but only up to a **maximum specified depth limit** to prevent long query times and hallucinations.
4. **Result Propagation:** When a subagent has completed its response, it must cleanly return its result back to the calling agent.
5. **Implicit Reference Detection:** If the main LLM detects that the user attempted to reference a chapter, section, or page range without using explicit commands, it deploys a subagent with a prompt produced by the main LLM to collect information from that target using commands.
6. **Command Syntax & Placement:** All LanceDB retrieval prompts support commands placed at the very beginning of the prompt string:
    * `/chapter $chapter`: Fetch all chunks within the specified chapter (including all chunks within every section in that chapter).
    * `/section $chapter.$section`: Fetch all chunks within the specified section in the specified chapter.
    * `/pages $from-$to`: Fetch all chunks within the specified page range.

7. **Default Fallback:** If no command or implicit reference is entered, the system defaults to querying LanceDB without any filters.

#### ## 2. Architectural Design & Execution Workflow

##### Phase A: Offline Summary Generation (Preparation)

* **Process:** Immediately after a PDF textbook is parsed and chunked, the application iterates through each extracted chapter and section one by one.
* **Execution:** A dedicated call to the LiteLLM/OpenAI endpoint generates a concise summary for each specific chapter and section.
* **Storage:** These summaries are compiled and written to a designated local file so that runtime subagents can rapidly inspect structural breakdowns without flooding the context window.

##### Phase B: Runtime Agentic Orchestration Loop

1. **Intent Analysis & Evaluation:** The primary LLM analyzes the user query. If information is deemed insufficient or an implicit structural reference is detected (e.g., mentioning a topic covered in Chapter 4 without typing a command), the main LLM formulates a targeted subagent prompt.
2. **Subagent Command Issuance:** The subagent reads the chapter/section summary file to map the target topic to its exact structural identifier, formatting its query with the appropriate prefix command (`/chapter`, `/section`, or `/pages`).
3. **Recursive Spawning with Guardrails:** If the subagent requires further cross-referencing, it may spawn child subagents, strictly bounded by the `MAX_DEPTH` parameter to eliminate infinite loops and hallucination drift.
4. **LanceDB Filtering & Return:** The retrieval handler strips and parses the leading command token from the prompt, applies the corresponding `.where()` metadata filter or range constraint in LanceDB, retrieves the chunks, and passes the payload back up the chain to the calling agent.
